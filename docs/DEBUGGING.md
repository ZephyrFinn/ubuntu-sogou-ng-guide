# 排错过程：从能安装到能输入

以下是 2026-11-24 这台电脑上的记录。区分实测、解释和未验证事项，不把单机结果推广成所有 Ubuntu 的结论。

## 1. 最初的 openKylin 社区整合包

最初使用 `sunxfancy/sogou-ng-fcitx5-ubuntu` 的 `10.0.9.0.6` 组件。安装和链接检查通过，后来能够输入中文，但遇到设置入口空白、双拼方案按钮无响应、候选框靠近底部越界等问题。

这一步的教训：安装包存在、依赖满足或链接检查通过，只能说明安装结构满足条件，不能说明所有设置、候选窗和应用集成都可用。

## 2. 空设置入口与程序启动参数

通过 Fcitx5 查询该输入法配置时返回 `Configuration does not exist`。直接运行旧版 `sogou-ime-setting` 又显示空的引擎 ini 文件名，因此没有成功获取引擎。

旧版本程序需要明确的面板和引擎配置参数。新版则自带设置启动脚本和桌面入口，路径改到 `/opt/apps/com.cpis/`；不能继续照搬旧的 `/etc/cpis/` 命令。

旧版 XML 里的“双拼方案设置”按钮缺少相邻正常按钮所用的标识，也没找到独立方案页。这个发现提示界面功能未接完整，但并不能单凭 XML 断言底层完全不支持双拼。

## 3. 候选框位置问题：没有宣布解决

多屏和不同缩放下，候选框在屏幕底部可能越界；微信里也发生过看不到候选窗。

曾调用面板的 `AcquireWindowRect` 和 `Move`，将 `composition` 窗口向上移动。接口接受移动并返回新坐标，但用户反馈仍不行。一次性的窗口移动没有解决输入过程中持续发生的自动定位问题。

不能仅把 XRandR 的物理像素与 GNOME 的逻辑坐标直接比较后就认定根因。本记录怀疑多屏缩放的坐标处理，但没有完成严格坐标链路验证。**最终新版的多屏底部避让、微信位置问题仍是待验证项。**

## 4. 升级 Deepin 前端，补齐配套依赖

发现 Deepin 系列有更新的 NG。下载前端和主程序后，APT 报缺少 `cpis-engine-plugin-libime-v3-*` 和 `10.0.2-3` 词库。

继续查到 CPIS 开发方仓库的不同发行目录，找到 v3 插件与词库。最初使用搜狗 `1410` / CPIS `2259-deb11u1`，后来又对齐到开发方搜狗 `1418` / CPIS `2291-deb11u1`。依赖检查和安装都通过，**但中文引擎仍初始化失败**。

版本混用曾被怀疑是原因；整套更新后失败仍在，不能把该假设写成结论。

## 5. 排除仍运行的旧进程

曾发现旧版 `/usr/bin/cpis-engine-service` 和旧的 `ISE_NODE --ini=/etc/cpis/...` 继续运行，D-Bus 名称 `com.cpis.engine` 也仍被旧 PID 持有。

确认命令行和当前用户后，正常退出这些旧进程，由 `/opt/apps/com.cpis/bin/cpis-engine-service` 接管。后来完整重启后也验证了新版本实际加载。

**这修复了新旧组件混用的问题，但并未修复独立存在的初始化失败。**

## 6. `Engine not initialized` 的关键对照

普通日志只有 `Engine not initialized`，它是失败结果，不是根因。

使用独立 D-Bus 会话、独立测试 HOME、独立测试 UID，以及同一份 CPIS 运行库和 v3 拼音插件做对照。测试没有向微信或其他应用发送文字，也没有使用个人词库。

跟踪显示插件读到 ini 并打开了 `libSogouShell.so`，在继续初始化前退出。Deepin 前端随包签名授权 XML 的 `os_white_list` 只包含 Deepin/UOS 名称，没有 Ubuntu。这个静态发现起初只能算疑点。

随后改为读取开发方另一前端包所附的**原始、未修改**配置和授权目录，得到以下对照：

| 测试条件 | `ni` 的结果 |
| --- | --- |
| Deepin 原始授权目录 | 无候选，状态 `-99`，日志显示未初始化 |
| 同版本麒麟原始授权目录 | 初始化成功，状态 `0`，候选含“你、尼、呢” |

在其余测试条件保持一致时，切回 Deepin 目录又失败。这个对照使“前端包及其运行条件不匹配”有了比单纯版本猜测更强的证据。但程序没有直接返回可解释的授权错误码，不能断言白名单字段是唯一内部判断。

最终采取的做法是**安装完整的麒麟前端包，移除 Deepin 前端，保留同版主程序和运行库**。没有编辑签名授权 XML、替换系统身份或二进制补丁。本机完成安装后，独立引擎调用再次返回中文候选；用户随后反馈“有字”。

麒麟包没有出现那一段白名单，不代表开发方正式保证 Ubuntu 兼容；应继续遵守包自身许可和适配范围。

## 7. 小鹤双拼重复解码

初始化成功后，用户反馈输入 `nihk` 得到“你哈哦”。

此时有两套设置同时存在：

```ini
; 前端 keyflow.ini
[KEYFLOW_SETTING]
shuangpin_enable = true
shuangpin_scheme_name = default/XiaoHe.ini
```

```ini
; 底层旧式 env.ini（出错状态）
QuanPin=0
ShuangPin=1
ShuangPinName=XiaoHe
```

前端将 `nihk` 解成全拼 `nihao` 后，底层又按双拼解释。隔离测试直接向底层输入 `nihao`：

| 底层设置 | 候选及组合 |
| --- | --- |
| `ShuangPin=1` | “你哈哦”，组合 `ni'ha'o` |
| `QuanPin=1, ShuangPin=0` | “你好”，组合 `ni'hao` |

修正方案：**前端小鹤保持开启，底层改为全拼**。两份旧式用户 env.ini 如存在都需核对，运行中的引擎也要同步。仓库配置工具正是实现这一点，不修改方案的键位定义。

## 8. 当前舒适配置及验证边界

按用户选定的习惯，采用小鹤、Shift 切换、简体半角、中文标点、每页 5 候选。前端配置写入用户 `keyflow.ini`；运行时通过面板 `RewriteEngineStat` 更新 `config_*` 状态并读回。

例如文件键 `default.fullshape` 对应运行时键 `config_default_fullshape`。底层双拼则通过引擎 `SetValues` 的 `user.env:QuanPin` / `user.env:ShuangPin` 设置。两类接口不同，不能只改一个状态栏选项就假设整个链路一致。

配置项读回成功不等于所有应用已验证。发布时仍需让使用者逐项测试：`nihk` 选词、长句、Shift、数字和标点、重启后的保持情况、微信、屏幕边缘及多屏缩放。

## 没有采用的网上办法

- 清空整个词库或配置目录：没有证据表明是用户词库损坏。
- 安装后端看门狗：它针对后端退出或连接断开，不能解决本次可重复的初始化失败。
- 移除厂商 Qt 库：相关成功案例多是传统 Fcitx4 版的符号错误，本次 NG 错误链不同。
- 仅凭状态栏、版本号或 `SetMode=0` 宣布修好：独立候选测试才暴露了初始化仍然失败。
